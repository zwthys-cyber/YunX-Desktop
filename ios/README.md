# YunX iOS（开发中）

SwiftUI 原生应用，最低 iOS 17.0，支持 iPhone / iPad；设备版为 arm64，面向用户已有的 TrollStore 环境。完整交付以 [移植验收表](PORTING.md) 为准，目前尚未达到最终验收。

## 构建与验证状态

最后完整成功的基线为 [`6a7c90a`](https://github.com/zwthys-cyber/YunX-Desktop/actions/runs/42859538393)：192 项模拟器测试零失败、独立 Java 对 iOS 加密备份的反向解密、主应用与分享扩展设备编译及 IPA 打包成功。

该轮包含真实钥匙串访问、Swift/Go HTTP 代理、共享任务配额、实际 HTTP 503 退避重试、目录迁移、GitHub 鉴权/ZIP/镜像策略、断点加密，以及原生 HTTP 共享限速的实际字节传输测试。原生账号请求头已通过真实 HTTP 请求、跨源重定向、Keychain 重读与磁盘无明文凭证检查，引擎并发与 Tracker 设置重启恢复也已通过。新增文件保存用例覆盖保留缓存、发布后恢复、取消及同名保护；Go 侧另通过原生和三种浏览器回退的真实 TLS 协议协商、文件大小不匹配拒绝、预读复制故障、暂停恢复、共享速率和缓冲预算用例。后续保存中断窗口、网盘来源刷新、补充证书检查和慢连接改动须单独查看 [GitHub Actions](https://github.com/zwthys-cyber/YunX-Desktop/actions?query=branch%3Aios-port)，不能直接继承旧提交的成功结论。

当前没有真实平台账号、iOS 17 设备安装或 TrollStore 共享容器验收记录。确定性的接口用例及较新 iOS 模拟器测试不能替代这些结果。早期失败与修复过程可查 Git 历史和 Actions，本页描述当前实现及其限制。

## 获取开发版 IPA

1. 打开上述 Actions 页面，选取 `ios-port` 分支的成功运行，核对提交号。
2. 在 Artifacts 下载 `YunX-iOS17-TrollStore-dev`，解压得到 IPA 和 SHA-256 文件。下载 Actions 产物通常需要登录 GitHub。
3. 将 IPA 分享给目标设备上的 TrollStore 安装。编译、签名结构和 ZIP 检查通过不等于已证明该设备能安装运行。

工作流同时保存测试结果、构建日志、原生引擎对应源码和版本信息。失败时先查看出错步骤，再查看 `YunX-iOS-build-log` 等产物；不要把失败运行或旧提交的 IPA 当作最新交付。

所有构建、自动测试和打包均在 GitHub 托管 macOS 运行机完成。当前服务器只读取、编辑和推送源码，不执行构建或验证脚本。修改 `ios/` 下的源码、资源或 `.github/workflows/ios-ipa.yml` 并推送到 `ios-port` 会触发流程；仅更新 Markdown 文档不重新编译，也可在 Actions 手动运行。

## 网盘与账号

已接入夸克、UC、123、光鸭、蓝奏优享、迅雷、百度、139、115 和蓝奏。包含各平台适用的登录、分享/个人目录、分页、取链及文件管理/转存流程。异步操作须获得明确完成结果才报告成功；批量递归有文件、目录和页数上限。

平台能力与账号权限不同：百度/迅雷分享文件可能需要用户明确转存后再取链；蓝奏个人文件生成分享链接前单独确认，不支持的文件夹移动/分享直接转存不会伪装成成功；139 使用官网 authorization；蓝奏优享不静默忽略不支持的提取码。验证页、过期参数、会员、付费和访问控制由平台决定，真实接口兼容性仍需账号验收。

账号、备注、主账号及辅助字段保存在 Keychain；支持独立网页会话登录及手动凭证。`.yunx` 备份采用口令派生密钥和 AES-GCM，包含与桌面 Java 实现的双向互操作测试。备份需要用户自行保存口令。

中文口令解析在用户确认后才发送第三方服务：先尝试迅雷，再尝试星海。不会附带已保存账号凭证，也不将口令原文写入历史或日志。

## 下载与文件

- 普通文件使用 URLSession；符合策略的公开 HTTPS 文件可使用系统后台会话，鉴权请求及手动代理使用前台会话。已有后台任务在启动后重新关联，其他任务需手动继续。系统可能延迟或暂停后台传输，强制退出后需重新打开应用。
- 原生 Gopeed 在进程内处理多连接 HTTPS、HLS、磁力、BT 种子和 ed2k；HTTP API、Web 和 MCP 服务关闭。HTTPS 支持 1–512 个连接，超过 32 个需确认，可提供预期整文件 SHA-256。P2P 支持 Tracker/DHT 设置及 peer 概览，实际公网和后台行为仍待设备验收。
- 网盘浏览页可选择原生多连接下载，十个平台分别保存连接数，单文件和目录批量使用同一选项。Cookie/Authorization 经 Keychain 运行时提供，原生任务记录不写入这些请求头；平台提供正数文件大小时完成前强制核对。入口已通过上述编译回归，真实网盘仍需账号及设备验收。
- 新增网盘原生任务保存来源及手动刷新直链：提取码和文件令牌放入 Keychain，仅记录随机上下文 ID；刷新使用原账号当前凭证，重新读取原目录以获取新的文件令牌，再请求直链。原账号移除、文件消失或权限变化时停止，不默认改用其他账号，也不自动转存。刷新需确认从头创建新任务，旧任务及片段保留；蓝奏个人文件会重新生成公开分享链接。此新增路径待对应提交的云端及真实平台检查，系统会话及旧任务需重新解析。
- 原生 HTTP 文件共享限速已通过云端共享预算、取消和实际传输测试，单位 KiB/s，0 表示不限；设置变化及暂停可唤醒等待者，限速等待不计入网络无进度超时。只覆盖原生 HTTP 文件读取，普通 URLSession、HLS 及 P2P 不在范围内，不能视为已完成跨引擎全局限速。
- 原生 HTTP 传输页提供 HTTP/2 和 16–4096 KiB 读缓冲设置；HTTP/2 影响之后建立的连接，已有任务暂停后继续可应用新缓冲，单任务连接缓冲合计上限 64 MiB。关闭 HTTP/2 时原生及浏览器回退均强制 HTTP/1.1；HLS、系统会话和 P2P 保留各自方式。真实 TLS 协商、自动回退及缓冲预算已通过上述云端检查；补充证书根信任用例仍需下一轮检查。
- 原生 HTTP 慢连接重连新增可配置的 4–10240 KiB/s 阈值与 5–600 秒窗口，默认关闭。仅支持有可靠 If-Range 标识的 Range 文件，保留已写入前缀；启用限速时暂停低速判定，预读交接停止旧监控，不使用已判定低速的解析响应回退。新增阻塞响应、限速/交接隔离和真实 Range 重连字节检查，待对应提交检查；系统会话不应用此设置。
- 统一调度已接入 URLSession 与原生引擎的共享任务配额，包含启动后台恢复屏障、物理取消后释放配额及过期回调隔离；共享配额及真实传输用例已通过。瞬时网络故障和指定临时 HTTP 状态最多自动退避重试三次，不自动重试认证或证书错误。
- 下载记录不保存账号请求头，跨源重定向移除 Cookie/Authorization。系统断点档案另用 AES-GCM 加密，密钥放入设备 Keychain；旧档案读取时迁移。任务身份参与校验，解密失败保留原文件。
- 可编辑保存文件名、复制直链、暂停/继续/删除、预览和系统导出。失败任务置顶，同名文件不覆盖；删除记录保留已完成文件。
- 普通下载包含「正在校验保存」阶段：在应用私有目录保留完整文件，由可取消任务进行媒体检查、SHA-256 校验及目标目录复制。目标文件发布前记录名称和摘要，重启后可手动继续保存；完成记录成功落盘后才清理私有副本。需预留额外临时空间，主要恢复路径已通过上述云端检查；补充中断窗口检查及外部文件提供器真机验收仍待完成。
- 下载保存目录迁移会暂停任务并关闭引擎，逐文件复制及 SHA-256 核对后更新稳定路径，保留原目录和恢复日志。应用缓存、数据库和 Keychain 留在私有容器。外部文件提供器授权、断开与恢复仍需真机验收。

全局带宽限制、分片级摘要、视频/GitHub 各自的连接设置、慢连接策略、直链刷新及外部目录保存验收尚有差距，详见验收表。整文件 SHA-256 不等于逐片校验；前台进程内引擎不等于后台常驻。

## 视频、图集与集成

已接入哔哩哔哩、Pixiv、微博、快手、AcFun、抖音和小红书。支持平台实际返回的作品/清晰度、原生预览、图集缩放、B 站 DASH 合轨、兼容片段拼接以及 JPEG/MOV Live Photo 配对。合轨、拼接和动态照片已有真实 H.264/AAC/JPEG 云端样本用例；照片库写入、设备播放和实际平台仍需验收。

HLS 播放通过随机 token 的本机回环代理重写播放列表及分片，不向 CDN 转发平台账号凭证；DRM 播放和携带账号凭证的原生 HLS 下载不在此路径支持。Pixiv ugoira/小说、番剧/课程等独立业务没有实现，不将 ZIP 或 m3u8 冒充图片/视频文件。

内置浏览器只读取已加载页面的 DOM 和资源条目，按类型预览并交给相应解析入口；不会读取 Cookie 或自动代表用户下载。分享扩展接收 Safari 等应用明确分享的链接/文字，在主应用确认后填入；使用 App Group 队列，容器不可用时提示改用复制粘贴。不能接管其他应用的全部网络或下载行为。

## GitHub、网络与设置

GitHub 支持仓库/用户/组织、文件目录、Releases、README，以及含斜杠分支的 tree/blob 链接确认。新增 Fork 来源、按需分批读取目录最后提交时间，以及将分支解析为确定提交后下载 ZIP。ZIP 格式检查拒绝错误页，私有下载始终走官方 API；请求使用仍存在的所选账号，401 仅清除实际被拒绝的旧凭证，迟到响应不删除替换后的 Token。对应离线用例已通过上述回归，私有仓库仍需真实账号验收。

公开 raw/Release 文件可主动启用五个镜像之一、自定义前缀或自动测速，默认直连。镜像失败可回退原始地址一次。带账号请求头、私有 API 和更新包不交给第三方镜像；测速需发起实际样本请求。Contents API 文件下载有 100MB 上限，普通目录最多返回 1000 项。

代理提供系统、原生直连及手动 HTTP/HTTPS CONNECT/SOCKS5，凭证在 Keychain 中。WebKit 的直连选项仍跟随系统，原生 Gopeed 暂不解析系统 PAC；HTTP 代理不涵盖 P2P 对等流量和 UDP。修改应用于新连接。

设置包含深浅主题/强调色、历史/收藏搜索与重用、用户授权后的完成通知，以及固定事件/数字字段的诊断日志。日志不包含原始链接、口令、请求头或未经处理的引擎错误，按 3×256KB 轮转并可过滤导出。

更新只识别本仓库 `ios-vX.Y.Z` 正式版本及唯一官方 IPA，要求 SHA-256 和兼容的最低系统声明。自动检查默认关闭，启用后最多每六小时检查一次。用户导出并交给 TrollStore 安装；不会自动替换当前应用，也不会把 Windows 安装包当作 iOS 更新。
