# YunX iOS 移植（开发中）

完整交付以 [移植验收表](PORTING.md) 为准；当前未完成，不作为最终交付。

目标：将桌面版完整的用户功能移植到 iOS 17.0，供已安装 TrollStore 的设备使用。

**当前不是完整移植版。** 当前已编写夸克 / UC 网盘、B 站单文件视频、Pixiv 原图适配、网页登录与基础下载，其他平台和完整下载引擎仍在移植，不能替代桌面版。已配置 GitHub Actions 设备版编译与 IPA 打包，具体成功状态、产物和日志以对应 Actions 运行记录为准；未做真机安装与运行验证。

## 操作约束

按仓库使用者最新授权，当前代理服务器可读取、编辑和推送源码，但不编译、不运行测试或验证脚本；编译、自动测试及打包只在 GitHub Actions 执行。iOS 构建使用 GitHub 托管 macOS runner，不创建会触发上游 Windows 构建的 PR。也保留用户自行在本地 Mac 构建的方式。

## 媒体文件落盘校验（开发中，待云端检查）

媒体图片按实际 ImageIO 容器类型修正扩展名；无法识别的图片不作为完成文件保存。单文件视频拒绝明显的 HTML/JSON 错误页、空响应及误走普通下载的 m3u8。这是媒体类型检查，不替代完整解码、官方摘要比对或真机播放验收。旧任务缺少媒体标记时保留原行为。

## 抖音 / 小红书作品页读取（开发中，待云端检查和真机）

新增两个平台的标准作品和短链识别，保留小红书原查询中的 `xsec_token`。解析时打开独立 WKWebView 官方作品页，由用户完成登录/验证后手动读取；可将所选账号 Cookie 写入对应平台域的临时会话，不自动保存该次登录。读取抖音 SSR/页面详情数据及小红书已加载状态，不合成 API 签名，不把 Cookie 注入 CDN 下载。

读取结果必须对应原作品标识，抖音仅 DOM 图片兜底不作为完整结果，缺图、图/动图错位或视频笔记只有封面时拒绝返回。动态照片仍分开提供静图和视频部分。当前未实现完整 Live Photo 合成、这些平台的登录有效性验证；小红书图集已编写最多 4 个并发的原图候选 HEAD 探测，仅确认图片响应后替换；缺失、验证失败或网络错误时保留原顺序的平台地址并提示可能带水印。网页兼容性、作品访问与播放均待设备验收。

## AcFun 与 HLS（开发中，待云端检查和真机）

新增 AcFun 标准 `ac` 作品链接、嵌套播放 JSON 和平台返回的各 HLS 档位。HLS 不通过直链下载器保存播放列表，而是交给原生引擎解析、分片和合并；输出名使用引擎实际计划的 TS/fMP4 等容器，任务在「下载 → 引擎任务」查看。此路径不接受账号 Cookie/Authorization。已编写 HLS 在线预览：仅监听 127.0.0.1 的随机端口并使用随机 token，重写播放列表/分片/密钥/初始化段路径，HTTPS 上游使用安全媒体请求头，不转发账号凭证，流式传输并随播放器关闭。只为本地网络设置 ATS 例外，不全局开放明文。受 DRM 保护的播放流程不在此路径处理。仍需云端回环代理测试和真机播放验收；多分 P AcFun 和 TS 转 MP4 尚未完成；不将 m3u8 冒充 MP4，不宣称完整媒体功能已经验收。

引擎冷构建会在 GitHub 执行上游基于本机测试 HTTP 服务的 HLS 端到端测试，覆盖 Referer、AES-128 换钥、ByteRange、暂停与持久化恢复，不访问实际视频平台。iOS 的对应运行与设备性能仍需验证。

## 快手媒体（开发中，待云端检查和真机）

新增快手短链/作品页、受限域名 HTTPS 跳转、移动 UA 的 `window.INIT_STATE` JSON 解析、视频与图集。JSON 只做结构解析，不执行页面脚本；多个候选作品且无法匹配目标时拒绝返回，避免错下推荐内容。跨至 chenzhongtech 分享页时不转发快手账号 Cookie，CDN 下载不携带 Cookie。平台返回验证页或结构变更时会提示失败，需实际平台与设备验收。

## 微博媒体（开发中，待云端检查和真机）

新增微博 status/detail、用户作品链接、tv mid 与视频 fid 链接；支持单文件视频、fid 返回的不同档位、原图、静图与动态照片视频部分，以及一层转发回退。图集缺原图则拒绝返回不完整结果；返回登录/验证 HTML 时拒绝解析，不复述服务端错误正文。媒体下载不携带账号 Cookie。微博可手动保存 Cookie 用于解析，目前未实现账号有效性验证或 Live Photo 合成，不能标记完整平台验收通过。

## B 站 DASH 与原生合轨（开发中，待当前云端检查）

登录后可优先请求平台 DASH 音视频，按实际返回的画质选择 H.264/HEVC 视频和 AAC 音频；同档优先 H.264，不虚报请求画质。分轨不足时带提示回退单文件的全部片段。在线预览仅使用额外取得的完整单文件流，画质可能不同；没有该流时提示下载后播放。

分轨由原生 HTTPS 引擎下载，合轨任务独立持久化并可暂停/继续；重启需手动继续。两个轨道完成后用 AVFoundation Passthrough 无损输出 MP4，检查轨道和时长，输出采用隐藏暂存及不覆盖文件的移动。下载/导出失败不标记完成，分轨保留重试。完成文件可播放及系统导出；删除记录保留文件。尚未完成番剧/课程、跨片段拼接、分轨直链自动刷新与真机性能验收。

云端测试使用生成的黑色视频/AAC 静音素材，检查真实 MP4 合轨、双轨、时长、可播放标记及拒绝缺音轨和覆盖已有文件。

## 原生 HTTPS 多连接下载（开发中，待当前云端检查）

「下载 → 引擎任务」可新建 HTTPS 文件直链，设置 1–512 个连接、可选文件名及预期 SHA-256。超过 32 个连接需确认；不支持 Range 的服务由引擎回退顺序读取。摘要不匹配不会标记成功或显示完成文件导出入口。此入口不接受账号请求头，也不直接下载 m3u8。当前原生队列与旧 URLSession 队列独立，尚未完成统一调度、全局限速或后台验收。

新增云端模拟器测试：使用 127.0.0.1 测试服务实际传输 8MB 固定数据，检查非零 Range、完成字节一致及错误 SHA-256 拒绝；不访问实际文件站点。

## 原生 P2P 引擎（开发中，待云端构建和真机）

「我的 → P2P 下载引擎」接入固定源码版本的 Gopeed，支持磁力、ed2k、导入种子、任务暂停/继续/删除记录、完成文件导出、Tracker 和 DHT 配置。不是桌面 EXE 或远端服务器代理：GitHub macOS runner 使用 gomobile 构建 arm64 设备与 arm64 模拟器 XCFramework，静态链接到应用，默认不开放 HTTP 管理端口。引擎有独立持久化目录，完成文件位于 Documents/P2P，每个任务单独目录。删除记录保留文件。

DHT 默认关闭，手动开启后需重启应用重建连接；Tracker 不自动从第三方订阅。前台运行不代表长期后台可用；已编写 Peer/做种概览（按引擎实际字段展示，不虚构节点数），尚需云端及设备网络/恢复验证。CI 只解析生成的本地测试种子，不连接真实下载资源。构建同时上传固定版本及修改后的引擎对应源码，最终分发需保留对应源码及 GPL-3.0 声明。

本地 Mac 若自行编译，还需 Go 1.26+，先执行 `bash build-engine.sh`；服务器仍不执行此步骤。GitHub 首次原生引擎冷构建可能较慢，后续使用按源码和 Xcode 版本隔离的框架缓存。

## 123 云盘（开发中，待当前云端检查）

新增 123 分享链接/提取码、分享与个人目录游标分页、账号密码登录及 JWT 验证、分享/个人盘取链和下载包装 URL 解码。账号密码仅发往官方 `user.123pan.cn`，仅保存 JWT；API 请求签名复用桌面版 CRC32 算法。CDN JSON 跳转最多 5 次，探测流最多读取 8KB，API 响应限制 2MB，API 鉴权不随 CDN 下载发送。不绕过账号、流量、会员或验证限制；真实登录与取链仍待平台及设备验证。暂未实现 123 转存管理。

## 认证备份（开发中，待当前云端检查）

「我的 → 认证备份」支持至少 8 位口令加密导出 `.yunx`，解密后先预览、确认再合并到 Keychain；相同平台/凭证合并，其他本机账号保留。采用与桌面版相同的 PBKDF2-HMAC-SHA256 / AES-256-GCM 封装，读取 V1（10000 轮）和 V2（210000 轮），仅导出 V2。辅助令牌字段随账号保留，备份不写明文凭证到临时文件。GitHub Actions 使用独立 Java/JCE 生成互操作向量。桌面版部分网盘恢复器只有一行主账号模型，不保证其能保留 iOS 备份中的全部同平台账号。

账号支持设置主账号；已接入当前平台的主账号默认选择及账号备注编辑；各平台辅助令牌的实际业务使用仍需逐项接入。未运行真机迁移验证，不据此标记完整移植完成。

## 网盘递归批量下载（本轮新增）

夸克/UC 目录页支持确认后递归下载当前目录，枚举成功后才开始取链。限制为 500 个文件、100 个目录和每目录 200 页；超过上限、重复分页或枚举失败时不创建这批任务，提示进入子目录分批操作。去重文件/目录 ID 以避免循环。下载保持扁平存储，子目录名以 `_` 合并到文件名，不宣称保留目录结构。单文件取链失败会计数并继续；取消只停止后续添加，已加入的任务在下载页管理。

## 下载队列与链接收藏（本轮新增）

完成文件可在下载页计算并保存 SHA-256，流式读取且在后台线程计算，不阻塞界面。该值用于用户自行比对，不宣称已匹配官方校验值。

下载支持最多 1–6 个同时任务、按加入顺序启动等待任务、全部暂停及全部继续。降低并发数不打断活动任务，后续任务等待空闲位置。应用重启后仍需手动恢复任务，尚未实现后台会话、分片或限速。

「我的 → 设置与收藏」可切换跟随系统/浅色/深色，管理最近 200 条历史及不限历史条数的收藏。网盘、媒体和 GitHub 输入页可从历史重新填入。网盘记录包含分享提取码，使用本应用受保护文件存储；不记录账号 Cookie/Token。清空历史保留收藏，删除收藏需单独删除。API 解析失败的有效格式链接也会保留为输入历史，不表示解析成功。

## GitHub 浏览模块（本轮新增）

支持输入 `owner/repo` 或 GitHub HTTPS 仓库首页，递归浏览默认分支目录、查看 README 原始文本、分页浏览 Releases 并下载公开文件和发布附件。可选择钥匙串内 GitHub Token，仅发送给 `api.github.com`；API 禁止自动跳转，文件下载不携带 Token。支持用户/组织仓库列表分页，以及账号页的 GitHub Token 有效性验证。私有文件下载、已接入 GitHub 渲染的 README HTML 显示（关闭脚本、独立临时会话），保留原文模式；镜像测速尚未实现。单个目录受 GitHub Contents API 的 1000 项限制。新增离线测试由 GitHub Actions 执行，本机不编译或验证。

## 当前编写内容（等待真机验证）

- SwiftUI 原生页面，最低系统 iOS 17.0，iPhone / iPad。
- URLSession 文件直链前台下载，暂停时保存系统断点数据，失败可重试；服务端不支持恢复时可能需要重新下载。
- 下载任务记录持久化，重启后由用户手动恢复；文件导出到系统分享面板。
- 夸克 / UC 分享文案与提取码识别，子目录浏览、每页 50 项与分页去重；个人网盘目录浏览。
- 夸克 / UC 游客或已保存账号的单文件免转存取链；复用上游协议，未绕过平台账号、会员、大小与风控限制。
- WKWebView 独立临时会话网页登录；保存前调用平台账号接口验证，支持手动 Cookie 和多账号选择。
- API 响应中的会话 Cookie 更新回写对应账号；下载保留 Referer、UA 和与直链绑定的游客 Cookie。
- 账号及逐任务请求头放入 Keychain；下载记录不写 Cookie，请求跨源重定向时移除 Cookie / Authorization。
- 下载文件使用平台文件名，已知文件大小不一致时拒绝保存，避免把错误页或替代内容当作下载完成。
- B 站 BV / av / b23 短链识别、分 P 选择、平台实际清晰度和单文件 MP4 分段下载。
- Pixiv 多页静态原图解析，核对页数、保留图片格式，单张或全部加入下载。
- B 站 / Pixiv 独立临时会话网页登录及行为验证；不凭 Cookie 名称判定已登录。
- MP4 在线预览使用公开 AVAssetResourceLoader 接口传递 Referer 和 Range；图片先落临时文件，再生成最多 2048 像素的预览，原图下载不缩放。
- 不向媒体 CDN 发送平台账号 Cookie；短链跳转也不携带账号 Cookie，API 不自动跟随重定向。
- 不覆盖同名文件，删除任务记录保留已完成文件。
- 系统默认网络安全策略仍生效，未为任意明文 HTTP 放开 ATS。

## GitHub Actions 编译与下载

修改 ios-port 分支下的 ios/ 源码或 iOS 工作流时自动构建。前往 [iOS 构建记录](https://github.com/zwthys-cyber/YunX-Desktop/actions?query=branch%3Aios-port)，打开成功运行，在 Artifacts 下载 YunX-iOS17-TrollStore-dev，解压取得 IPA 和 SHA-256 文件，然后将 IPA 分享给设备上的 TrollStore 安装。下载 Actions 产物通常需要登录 GitHub。

若 Fork 的 Actions 被 GitHub 默认禁用，需要仓库所有者在 Actions 页面启用。构建使用 XcodeGen 生成工程，Xcode 编译 arm64 设备版，最低 iOS 17.0，再做 ad-hoc 签名和 IPA 打包。权限仅配置应用标识和本应用 Keychain 分组，不请求越狱、跨应用数据访问或后台常驻权限。

工作流在 iOS 模拟器上运行确定性的模拟接口单元测试，覆盖分享码、UC 转存目录接口与分页、游客 Cookie、账号 Cookie 回写、敏感信息错误处理、跨源凭证隔离及旧任务兼容；另覆盖 B 站分 P、所有分段和实际清晰度、短链凭证隔离、Pixiv 缺页与动图拒绝、服务端错误脱敏以及 MP4 Range 解析和溢出处理；不在 CI 登录或请求真实平台接口。工作流还检查签名结构、arm64 架构和 ZIP 完整性；这些检查不等于设备安装成功或下载/账号等业务功能通过测试。编译失败时查看运行日志和 YunX-iOS-build-log 产物。

## 本地 Mac 编译

需要完整 Xcode、iOS SDK 和 XcodeGen；在 Mac 自行安装并选择 Xcode，完成首次启动配置。也可使用同一构建脚本进行本地编译。

在 Mac 下载本仓库的 ios-port 分支后：

```sh
cd ios
bash build-local.sh
```

脚本生成 Xcode 工程并构建设备版，进行无需开发者证书的 ad-hoc 签名，再打包为 build/YunX-iOS17-TrollStore-dev.ipa。也可先执行 xcodegen generate，在 Xcode 打开 YunX.xcodeproj 查看或编译。

**IPA 编译及打包通过不代表已通过 TrollStore 真机安装验证。** 本阶段仅使用应用标识和本应用 Keychain 权限，不承诺后台常驻、访问其他应用数据或绕过系统权限。

## 0.3.0 视频与图集

1. 可在「账号」登录 B 站 / Pixiv 或手动保存 Cookie；游客也可尝试解析，平台决定作品是否可见。
2. 在「视频与图集」选择平台与账号，粘贴链接或文案。B 站还支持 b23 / bili2233 短链与链接中的 p 参数。
3. B 站结果显示当前分 P 和实际返回画质；切换请求失败时保留上次成功结果。下载使用同一结果；多个视频片段分别列出和下载，不冒充已拼接文件。
4. Pixiv 核对多页原图数，支持单张或确认后全部加入下载。图片预览按需加载，超过 32MB 或无法解码时提示直接下载原图；静态预览不代表动图播放。
5. MP4 原生预览通过自定义资源加载器处理 HTTP 区间、防盗链请求头、200 回退跳过字节和取消请求，不使用未公开的 AVURLAsset 请求头选项。

**仍不支持** B 站 DASH 分轨合轨、番剧/课程等独立业务、跨片段拼接、Pixiv ugoira / 小说、HLS 下载和其余视频平台。画质、受限作品与登录有效性由平台服务端决定；不绕过会员、付费或访问权限。API 结构来自本仓库上游实现，真实平台变化、WebKit 登录兼容性、在线播放和设备安装都需要真机验证。

## 0.2.0 网盘使用方式与边界

1. 在「账号」中登录夸克或 UC，或手动保存对应平台 Cookie；网页登录如受 WebKit / 平台验证限制，可用手动方式。
2. 到「网盘」选择同一平台和账号（也可游客），粘贴分享文案，提取码可自动识别或手填；也可浏览个人网盘。
3. 进入目录，点击单个文件「下载」，再到「下载」查看前台任务及导出文件。

分享取链使用上游免转存流程，不创建或删除用户网盘文件。游客能否下载取决于平台限制。签名直链会过期，旧任务被服务端拒绝时应重新解析。跨源重定向不转发账号凭证，因此某些依赖跨域 Cookie 的 CDN 可能需要进一步适配。长时间后台下载、文件夹递归下载、P2P 与其他平台解析尚未实现。所有真实账号、下载可用性和 WebKit 兼容性均待设备验证。

## 平台差异

Windows 托盘、Win32 菜单、窗口定位、DPAPI、扫描 Windows 浏览器 Cookie、Chromium 桌面扩展下载接管、ffplay/EXE/DLL 不能原样在 iOS 使用。应分别设计为 iOS 导航与通知、Keychain、应用内网页登录、分享/Safari 扩展、原生播放器和链接到应用内的媒体库。

“完整功能”目标需要区分用户可完成的操作与 Windows 专用实现细节。TrollStore 安装不等于所有系统能力均可直接使用，受权限、WebKit、后台调度和引擎可移植性影响的项目需单独记录本机验证结果。
