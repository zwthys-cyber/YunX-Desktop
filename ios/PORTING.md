## 下载链路仍需补齐的具体差距

- 全局带宽限制必须同时约束系统会话和原生 HTTP 引擎；原生 HTTP 文件的共享、可取消速率预算已通过 180 项回归中的实际传输用例及 Go 并发测试，普通 URLSession/HLS/P2P 尚不覆盖。仅降低任务优先级或延迟进度刷新不能算限速实现。
- 分片级 SHA-256 校验与整文件 SHA-256 是两项能力。新增原生 HTTPS 文件按实际写入增量累计不超过 1 MiB 的段摘要，与断点进度共同持久化；恢复请求前及完成前重读各段并检查覆盖范围，损坏/缺失摘要不得完成或复用，临时 I/O 失败保留原文件。设置每任务摘要数量与活动流预算，超限停止。原生写入、预读交接、Range 暂停换链、磁盘篡改及实际 iOS 下载已通过 `4870fec` 的对应云端检查；系统会话、HLS、P2P 和旧任务仍不覆盖，不能据此称所有下载方式已完成分片校验。
- 十个网盘平台的独立连接数及原生下载入口已通过云端编译及打包；视频合轨/片段/动态照片源的按平台连接设置、任务快照及高连接数确认已通过 `8991483` 的完整云端检查。GitHub 文件/Release/源码 ZIP 的原生选项与独立连接数、格式核对和点文件导出，已通过云端检查；原生模式官方源、系统模式保留镜像/后台策略。普通视频单文件原生模式已通过云端检查。原生 HTTP/2、读缓冲、慢连接策略及真实 Range 换链已通过完整云端检查；系统会话及其他下载方式不继承这些设置。
